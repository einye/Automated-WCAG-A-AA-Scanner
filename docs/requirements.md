# System Requirements

## Non-Functional Requirements - Look, feel and experience

### ⚖️ Legal Clarity
The tool provides what the threshold is for compliance with WCAG and country laws (if any)

### 📃 Scores per Disability Groups
The tool provides accessibility scores for recognised disability groups (e.g. "Blind", "Deaf", "Colour-blind" etc.)

### ✌️ 2 Levels of Output (Complexity)
Output has two levels of presentation: developer-focused (detailed) and non-developer-focused (shows scores and overviews)
   - Each disability group has its own section containing output of what they can and can't do on the website
   - Dev's are given feedback on immediate fixes and examples of good practice
  
### 📚 Blog
Tool contains a blog for giving a foundation/fundamental info about building accessible websites

### 👥 Target Audience
Tool is built for people who are just getting into accessibility
- Simple Results
- Summarised pass/fail per element
- Clear, minimalistic fix suggestions

### LIst Rules for each Element 
Dev can check all the conventions and practical features required to ensure accessibility for each disability group

## Functional Requirements

### Data Warehousing
Store the number of websites screened and evaluated, and their scores on each disability group.
